# Phase 1 UI Polish 设计说明

## 现状问题

- 移动端首屏由品牌横幅、搜索框和四个独立分类胶囊连续占据，地图虽铺满屏幕，却没有成为视觉主体。
- 搜索、快捷入口、地图控件、建筑卡片、Toast 和加载卡片分别使用不同圆角、阴影、描边与玻璃效果，界面更接近功能 Demo，而非统一的地图产品。
- 绿色品牌色和深色选中态偏离南邮蓝；建筑、地表、道路与 POI 的色彩来源分散，缩放层级也不够清楚。
- 定位、指南针和回到校园分属不同控件；移动端 Toast 会压住地图归因，选中建筑卡片也没有形成稳定的 Place Peek 模式。
- “NJUPT SMART CAMPUS”“合成演示数据”等常驻标签抢占注意力；演示数据需要明确，但应放在低干扰的地图归因区。

## 设计原则

1. **地图优先**：移动端顶部只保留一个 50px 搜索入口，底部只保留共享快捷托盘；其余信息在需要时出现。
2. **南邮识别**：以 `#003B70` 为品牌主色、`#2563EB` 为交互强调色，搭配白、暖灰和浅蓝灰；品牌提示融入搜索入口，不另设横幅。
3. **共享表面**：快捷入口和地图控制分别形成一个整体容器，统一 12px 圆角、轻阴影、44px 可点击区域与 180–220ms 动效。
4. **渐进呈现**：远景优先边界、主路、主要建筑；放大后再显示步道、普通 POI 和更多标签。
5. **上下文卡片**：建筑选择在移动端采用 Mini Bottom Sheet，在桌面端采用左下紧凑 Place Peek；只展示真实可用的信息，不制造导航入口。
6. **可访问与可维护**：保留键盘焦点、ARIA、Safe Area、定位失败/越界和加载错误；全局 UI Token 与地图 Palette 分离，组件自管样式。

## 参考与取舍

- **Apple Maps / 高德地图 / 百度地图移动端**：采用“顶部单搜索 + 底部快捷入口 + 地点底卡”的成熟信息架构，让地图保持主舞台。
- **Mapbox / MapLibre 产品化案例**：将定位、指南针和复位收敛为右侧统一控制组，并通过缩放阈值控制标签密度。
- 本阶段不实现搜索、筛选、路线、导航或 AI 能力；所有入口只给出克制的 Phase 2 提示，避免把占位交互伪装成已完成产品功能。
